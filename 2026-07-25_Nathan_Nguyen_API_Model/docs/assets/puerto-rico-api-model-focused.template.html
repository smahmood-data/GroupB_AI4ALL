How the dengue forecast works.

The system makes two related predictions for each week: how many dengue cases may be reported and the chance that the week will cross the model’s outbreak cutoff.

What “outbreak” means here

An outbreak week has more cases than the seasonal cutoff. That cutoff marks the highest 25% of comparable weeks in earlier years. It is a model definition, not an official government declaration.

Training history—complete island weeks
Lowest tested case error—cases per week on average (MAE)
Best alert balance—precision and recall combined (F1)
Stricter weather test—weeks with complete archived forecasts

How the seasonal outbreak cutoff is calculated

For each week of the year, the model looks only at earlier training years and gathers comparable weeks within two weeks on either side. The cutoff is the 75th percentile: the point above which the highest 25% of those case counts fall. A target week is labeled an outbreak only when its cases are above that cutoff.

The cutoff changes through the year. A count that is unusual in spring may be normal during the usual fall peak.
Complete architecture

From source data to a monitored forecast

Each layer has one job. The system saves what it knew when a forecast was issued, then scores that forecast after the official case count arrives.

1CollectTwo public API systems

Puerto Rico health data

Weekly PCR and IgM cases, total cases, hospitalizations, report dates, and later revisions.

Open-Meteo weather data

Daily weather from six island locations, using historical, forecast, and archived forecast endpoints.

2Check and summarizeOne row per complete week

Health-data checks

Standardize dates and numbers, combine confirmed case fields, keep complete weeks, record revisions, and leave missing case weeks missing instead of inventing counts.

Weather-data checks

Reject invalid values, summarize daily readings into weeks, combine six locations, and record whether each forecast used live or archived weather.

3Create inputsPast information only

Season

Sine and cosine variables describe where the week falls in the annual cycle without a hard break between December and January.

Weather now and earlier

Temperature, rain, precipitation hours, humidity, dew point, soil moisture, evaporation, wet days, and maximum daily rain at 0-, 2-, 4-, and 8-week lags, plus 4- and 8-week summaries. The case-count branch also uses heavy-rain days and dry spells.

Available health history

Recent or delayed cases and hospitalizations, changes, 4- and 8-week averages, hospitalization rate, and the age of the newest report.

4Choose a routeMatch real reporting conditions

Exact recent cases

Used only when the latest case weeks are available before the forecast date.

Delayed cases

Uses the newest older report and tells the model how many weeks old it is. This is the current operational route.

Weather only

Used when no trustworthy case history is available. It is a fallback, not the preferred route.

5Run two branchesDifferent models, different jobs
Case-count branch

Three boosted-tree regressors

Estimate the median and two upper case levels. A tested persistence fallback replaces the median model when carrying the latest count forward is more accurate.

Outbreak branch

Boosted-tree classifier + probability adjustment

Estimate whether cases will cross the seasonal cutoff, then use logistic regression to adjust the raw score into a more realistic probability.

6Publish and learn safelyMonitoring, not self-training

Weekly public output

Forecast week, starting estimate, higher estimates, outbreak cutoff, outbreak probability, report age, and source dates.

Later scoring and guarded retraining

Save the input snapshot, compare predictions with later official cases, and retrain on schedule. A candidate replaces the current model only when required time-based checks do not worsen.

Models inside the system

Two prediction branches, stated plainly

“Boosted trees” means many small decision trees are built in sequence. Each new tree focuses on errors made by the earlier trees.

Case-count branch

HistGradientBoostingRegressor

Three regressors estimate the middle case count and two upper levels. They use quantile loss, which lets each model target a different part of the range instead of only predicting an average.

Outbreak branch

HistGradientBoostingClassifier + LogisticRegression

The classifier finds patterns linked with outbreak weeks. Logistic regression does not decide the outbreak by itself; it adjusts the classifier’s raw score so the final percentage is more useful as a probability.

The route matches the reports available that day

All routes use the same seasonal calendar and weather structure. Their difference is how much case history was actually available before the target week.

Variables used

What the model can see

A variable is one measurable input given to the model. A lag means the value came from an earlier week.

Season

Four circular calendar variables represent the annual cycle.

  • Week sine and cosine
  • A second sine and cosine pair for more flexible seasonal shape

Temperature and moisture

Each appears for the target week, 2, 4, and 8 weeks earlier, plus recent 4- and 8-week summaries.

  • Mean, maximum, and minimum temperature
  • Relative humidity and dew point
  • Topsoil moisture
  • Reference evapotranspiration

Rain

The model separates total rain from how it was distributed across days and hours.

  • Total precipitation and precipitation hours
  • Wet-day count and maximum daily rainfall
  • Heavy-rain-day count and longest dry spell for the case-count branch

Exact case history

Used only when reports are current enough.

  • Cases 1, 2, and 4 weeks earlier
  • 4- and 8-week case averages
  • Latest weekly change
  • Hospitalizations and hospitalization rate

Delayed case history

The same idea is anchored to the newest report actually available, even when that report is several weeks old.

  • Newest known count and earlier lags
  • 4- and 8-week averages
  • Hospitalizations and rate
  • Age of the report in weeks

What is not used

The model does not use information that appears after the forecast date.

  • No future case counts
  • No backward-filled missing case weeks
  • No finalized weather in the stricter archived-weather test
  • No personal or patient-level data
Time-based testing

Train on the past, test on a later period

Random k-fold testing would mix future and past weeks. The model instead uses expanding windows so every test prediction faces forward in time.

1 · Split by time

Train on earlier years and reserve a later year for testing.

2 · Refit all preparation

Thresholds, missing-value handling, models, and probability adjustment use training data only.

3 · Predict unseen weeks

The reserved weeks are held out: their outcomes did not teach the model that made their predictions.

4 · Move forward

Add the completed year to training, test the next period, and combine all later-week results.

MAE

How close were the case counts?

Mean absolute error (MAE) is the average number of cases by which a prediction missed. Lower is better.

average(|actual cases − predicted cases|)
R

How many outbreaks were caught?

Sensitivity, also called recall, is the share of real outbreak weeks that received an alert. The recall-focused setting accepts more false alerts to catch more outbreaks.

recall = outbreaks caught ÷ actual outbreaks

Why two scores are necessary

Case-count error and outbreak detection measure different jobs. A model can predict counts closely on average and still miss outbreak weeks. It can also catch more outbreaks by issuing more alerts, which lowers the share of alerts that are correct.

Limits

What this forecast cannot establish

The model is a research tool. Its outputs should support attention and further investigation, not replace official surveillance or clinical judgment.

Reports arrive late

The operational route currently relies on older case reports. Sudden recent changes may not yet appear in the health data.

Puerto Rico is combined

An island-wide forecast can hide important differences between municipalities and local health regions.

The evidence is still limited

The model has a relatively short weekly history and a small number of independently observed outbreak periods. Future performance may differ from historical tests.

Plain-language glossary

Technical terms used on this page

Each term is defined here and explained again where it first matters.

Outbreak week
A week with more cases than the seasonal top-25% cutoff used by this model.
Seasonal cutoff
A boundary calculated from comparable weeks in earlier training years. It changes through the year.
Starting estimate
The central case estimate. The delayed-case route currently carries forward the latest official count because that fallback tested better.
Higher estimate
An upper case-count estimate for outcomes above the starting estimate.
Classifier
A model that estimates which of two groups a week belongs to: outbreak or not outbreak.
Regressor
A model that estimates a number, such as weekly cases.
Boosted trees
Many small decision trees built in sequence so later trees correct earlier errors.
Probability calibration
An adjustment that makes predicted percentages better match how often outcomes occurred.
Quantile
A point in a predicted range. The 50th percentile is the middle estimate; the 80th and 90th percentiles are higher estimates.
MAE
Mean absolute error: the average number of cases by which predictions missed.
Recall / sensitivity
The share of actual outbreak weeks the model caught.
Precision
The share of outbreak alerts that were correct.
Specificity
The share of non-outbreak weeks the model correctly left unflagged.
F1 score
One score that balances precision and recall.
Brier score
The average squared error of the predicted probabilities. Lower is better.
Held-out week
A later week excluded from training and saved for testing.
Lag
An earlier value used to predict a later week, such as rainfall from eight weeks ago.
Rolling summary
A statistic over a moving window, such as average rainfall over the last four weeks.
Persistence fallback
A simple prediction that carries the latest known case count forward.
Guarded promotion
A rule that blocks a retrained candidate from replacing the current model unless required tests remain acceptable.
API
An application programming interface: a structured way for software to request data from another service.
Data route
The version of the model selected according to whether recent, delayed, or no case reports are available.
Input variable / feature
One measured value given to a model, such as rainfall from two weeks earlier.
ECMWF
The weather-forecast provider used for the stricter archived-weather test.
